## 一、项目定位

解决"懒得打开记账软件"的痛点，通过 **QQ 机器人自然语言记账** + **手机 PWA 只读看数据**，让记账摩擦降到最低。

---

## 二、核心架构

```
GitHub 仓库（zhan-zip/bookkeeping，已公开）
  └─ data/expenses.json   ← 唯一数据源（GitHub API 读写；MCP 带写 token，PWA 匿名/只读 token）
         ↑ GitHub API
   ┌─────┴──────┐
   │            │
PWA（手机只读）  QQ 机器人（记账 MCP）
  匿名/只读 token  MCP server（内部持写 token）
```

**数据放 GitHub 仓库**（规划时为私有，已改公开）的原因：
- 本地、服务器、手机都能读写同一份数据，天然互通
- 前期本地、后期服务器切换时数据零迁移
- 有 git 历史，误删可恢复
- 数据天然私密（规划时私有仓库；已改公开，PWA 匿名只读）

## 三、三大模块（核心逻辑）

### 模块一：余额（本月开销视角）
- 每月最后一天 00:00 清零
- 手动记一笔"收入：生活费 X"当期初（每月生活费可能不同）
- 实际收支逐条累加，每条流水带"当时余额"
- 月末余额为正 = 剩了；为负 = 花超
- **花超处理**：当月实际储蓄记 0，下月期初先扣一笔"补上月超支"

### 模块二：心愿储蓄（心理账户，纯记录）
- 只记"东西名 + 价格"，**不存"买没买"状态**
- 想买 → 进清单；真买 → 转正式支出并从清单消失
- "你真要买这个吗"流程：忍住→进清单；买→先看生活费够不够，够则扣生活费，不够按花超算
- **不动余额**（没花就是没花，钱自然还在余额里）
- 月末展示"守住了多少件、共多少钱"

### 模块三：实际储蓄（每月独立，不跨月累计）
- 每月 = 当月生活费剩余（余额为正的部分）
- 每月单独看，不自动跨月累计（用户自己心里有总积蓄）

## 四、收入分类（AA vs 真收入）

| 收入类型 | 举例 | 算不算真收入 |
|---|---|---|
| **真实收入** | 生活费、兼职、红包 | ✅ 算，进实际储蓄统计 |
| **AA 回款** | 朋友转来的垫付钱 | ❌ 不算，只冲抵支出 |

## 五、AA 记账公式（不配对）

- 垫付记"支出 + 类型=AA垫付"
- 回款记"收入 + 类型=AA回款"
- **不配对**（不指定回款冲抵哪笔垫付），只按总额冲抵
- 统计公式：
  - 实际花费 = 名义支出 − AA 回款总额
  - 实际收入 = 名义收入 − AA 回款总额
- 边界：AA 回款 ≤ 垫付才正确，超了不特殊处理（手动改）

## 六、分类体系（8 类，已定）

| 分类 | 定义 |
|---|---|
| **技术** | AI 相关：做项目、订阅套餐、服务器等 |
| **学习** | 课内：本子、笔、教材等 |
| **吃饭** | 日常吃饭 |
| **零食** | 零食饮料等 |
| **购物** | 非必需小玩意网购（心愿清单真买的也归这里） |
| **生活** | 日用品（家里给，较少） |
| **社交** | 出去玩吃饭 + 其他相关购物 |
| **出行** | 打车 |

**后期可改**。用户偏观察头一个月支出结构后再设分类预算。

## 七、预算

- **月总预算 + 分类预算**：都做，超支在月报标出
- **首月不设预算**：先观察支出结构
- 第二月起可设（如零食限额 ¥200/月）
- **预算仅参考**：最终判断看总生活费超没超，跟心愿储蓄无关

---

## 八、月报

- **触发**：每月最后一天 00:00 清零 → **次月 1 号早 6:00 机器人主动推送**（用户起床洗脸时看）
- 也可随时向机器人索要
- 数据机器人直接调软件，套模板（以后做成图片）
- **四块内容**：
  1. 生活费情况（发了多少、花了多少、剩或超）
  2. 真正存下（当月实际储蓄）
  3. 守住清单（心愿储蓄没买的，共几件多少钱）
  4. 分类预算超支报告（零食等分类预算超了标出）

## 九、数据层

- **存储**：GitHub 仓库 `data/expenses.json` 单文件
- **数据 schema**（每条记录）：
```json
{
  "id": "20260817-1",
  "type": "expense",          // expense / income / aa_advance / aa_return
  "amount": 25.5,
  "category": "餐饮",
  "note": "午饭",
  "date": "2026-08-17",
  "balance_after": 1775.0,    // 当时余额
  "created_at": "2026-08-17T02:45:00"
}
```
- **读写封装**：GitHub Contents API（GET 拿文件+sha → PUT 带 sha 防冲突，参考博客 admin 踩过的坑）
- 心愿清单：`data/wishlist.json`（只存东西+价格）

## 十、MCP server（机器人记账）

- **部署**：独立 server 进程，跟 qq-agent 一起跑；前期本地，后期跟 agent 一起搬服务器
- **为什么独立进程**：agent 本地时 MCP 本地，agent 上服务器时 MCP 跟着搬，代码不用改，只变启动位置
- **暴露工具**：

| 工具 | 作用 |
|---|---|
| `add_expense_tool` | 记一笔（金额/分类/备注/收支类型，自动带时间、自动算 balance_after） |
| `get_summary_tool` | 今日/本周/本月汇总（`year` 未实现，传非 today/week/month 会报错） |
| `get_category_stats_tool` | 分类占比 |
| `get_recent_tool` | 最近 N 笔流水 |
| `get_budget_status_tool` | 预算还剩多少 |
| `add_wish_tool` | 心愿清单加一条 |
| `buy_wish_tool` | 心愿清单真买 → 转支出 + 从清单消失 |
| `get_monthly_report_tool` | 月报完整数据 |
| `ensure_allowance_tool` | 确保本月有期初生活费 |
| `parse_expense_text_tool` | 自然语言解析"午饭25"等 |
| `list_categories_tool` | 获取所有分类（动态读取） |
| `add_category_tool` | 新增分类（去重、长度限制） |
| `delete_category_tool` | 删除分类（内置 8 类受保护） |
| `delete_expense_tool` | 删除流水（自动重算余额） |
| `update_expense_tool` | 修改流水（部分字段，自动重算余额） |
| `push_monthly_report_tool` | 生成月报推送文本 |

- **增删改**：机器人自然语言，任意带数据处可改（"删昨天那笔午饭"、"改第X笔金额"）
- **自然语言记账**：机器人收"午饭25" → LLM 解析成 {金额, 分类, 备注} → 调 add_expense。不做自动分类（万一分错手机不能改）

## 十一、PWA 前端（手机只读）

### 11.1 部署
- 技术：Vue3 + Vite + vite-plugin-pwa（autoUpdate）+ ECharts
- 部署 GitHub Pages（`zhan-zip.github.io/bookkeeping`）
- `base: '/bookkeeping/'`（必配，避免资源 404）
- **只读 token**：存 localStorage，只授权这一个仓库的只读（Contents read），无写权限（方案 B，接受低风险）

### 11.2 展示内容（全要）
- 余额/流水（每条带当时余额）
- 分类占比（饼图）
- 月度趋势（近 N 月柱状）
- 月报
- 心愿清单
- 实际储蓄累计

### 11.3 导航
- **底部中间浮动按键**（可隐藏/点击展开导航）
- 弹出导航：总览 / 流水 / 心愿 / 月报
- 点击遮罩或再点按键收起
- **不做侧滑抽屉**（避免灵感笔记最大的手势坑源）

### 11.4 颜色
- 黑白风：背景纯白、主文字纯黑、次要信息灰阶（对比度 ≥4.5:1）
- **只有"负数/超支"用红色**，其余一律黑白灰
- ECharts 配色走黑白灰阶，不用彩色

### 11.5 手势（极简）
- 只保留：**下拉刷新、滚动、点击**
- 不做：侧滑抽屉、左滑删除、右拉返回等（灵感笔记的坑源）
- 后续要加再评估

### 11.6 灵感笔记避坑清单（实施时必须规避）
1. 点击区 ≥44px（防误触）
2. 任何写操作有 toast 反馈——但 PWA 只读，这条主要给机器人侧
3. PWA 一开始就配 `base:'/bookkeeping/'`
4. PWA 用 `autoUpdate` + 自动注入 SW（registerSW.js），避免影响浏览器安装判定
5. 收起/隐藏态加 `aria-hidden`
6. 下拉刷新注意 `touch-action` 与页面滚动的冲突（用 `overscroll-behavior: none`）
7. iOS Safari 最左边缘右滑是系统返回，手势起点避开屏幕最左边缘
8. `e.buttons===0` 检查只对鼠标生效，触摸不依赖它判断
9. 不要把模型输出退化（重复发命令）当成网络问题——那是模型/服务侧

## 十二、已定决策记录

| 决策 | 结论 | 理由 |
|---|---|---|
| 数据存储 | GitHub 公开仓库 JSON | 免费、零迁移、有历史 |
| 记账主入口 | QQ 机器人（自然语言） | 用户懒得开软件 |
| 手机 PWA | 只读 | 避免写 token 暴露在公开网页 |
| PWA token | 只读 token 存 localStorage（方案 B） | 接受低风险，记账数据对他人价值低 |
| MCP 部署 | 独立 server 进程，跟 agent 走 | 本地/服务器切换零成本 |
| 余额结算 | 每月最后一天清零，不跨月累计 | 看本月开销视角 |
| 实际储蓄 | 每月独立，不跨月累计 | 用户自己心里有总积蓄 |
| 心愿清单 | 只存东西+价格，买后转移 | 干净，不留历史 |
| AA 记账 | 方式 A，垫付+回款，不配对 | 流水完整 |
| 月末日期 | 每月最后一天 00:00（非硬编码 31） | 2/4/6 月没 31 号 |
| 月报推送 | 次月 1 号早 6:00 | 用户起床洗脸时看 |
| 预算 | 首月不设，观察后设；仅参考 | 总生活费才是最终判断 |
| 收支都记 | 是 | 但 AA 回款不算真收入 |
| 自动分类 | **不做** | 万一分错手机不能改 |
| OCR 拍照 | **不做** | 截图跟手动说差不多 |
| 账单导入 | **不做** | 不想弄 |
| 真存钱/自动转账 | **不做** | 有风险，不用余额宝 |
| 购物链接识别 | **不做** | 拼多多拿不到标题，不值得 |
| 导航形式 | 底部中间浮动按键（可收起） | 最小交互面，避免侧滑抽屉坑 |
| 超支颜色 | 红色 | 唯一例外强调色 |
| 手势范围 | 下拉刷新 + 滚动 + 点击 | 极简，绕开灵感笔记 80% 手势坑 |
| 仓库名 | bookkeeping，PUBLIC | 已建：https://github.com/zhan-zip/bookkeeping |
